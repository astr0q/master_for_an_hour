1. Introduction
Master for an Hour is a web-based repair request management system that streamlines communication between customers who need minor home repairs, operators who coordinate the workflow, and masters (skilled workers) who carry out the jobs. The system manages the complete repair lifecycle from initial request submission through assignment, execution, and completion.

This document is the official reference for setting up and using the system. It covers all installation steps for both the backend and frontend, describes all user-facing features, and provides guidance for each of the three user roles.

The application runs as two independent processes that must be started together: a Django REST API on port 8000 and a React (Vite) application on port 5173. Both must be running simultaneously for the system to function.

3. Installation Manual
3.1 Backend Setup (Django)
The Django backend provides the REST API that the React frontend communicates with. Follow these steps in order.

1.	Open a terminal and navigate to the backend folder:
cd backend
2.	Create and activate a Python virtual environment:
python -m venv venv
venv\Scripts\activate          (Windows)
source venv/bin/activate       (macOS / Linux)
3.	Install required Python packages:
pip install -r requirements.txt
4.	Create a .env file inside backend/ with your Supabase credentials:
DB_HOST=aws-0-eu-west-2.pooler.supabase.com
DB_PORT=6543
DB_NAME=postgres
DB_USER=postgres.your-project-ref
DB_PASSWORD=your-supabase-password
5.	Start the backend server:
python manage.py runserver

Note: The .env file contains sensitive credentials. It must never be committed to version control. Add it to .gitignore before your first commit.

3.2 Frontend Setup (React / Vite)
The React frontend is a separate application that calls the Django API. Open a new terminal window for these steps.

1.	Navigate to the frontend folder:
cd frontend
2.	Install JavaScript dependencies:
npm install
3.	Start the Vite development server:
npm run dev
4.	Open a browser and navigate to: http://localhost:5173

3.3 Database Setup (Supabase)
The PostgreSQL database is hosted on Supabase. The database schema must be created before first use with the following six tables: profiles, services, repair_requests, request_updates, master_availability, and notifications.

1.	Log in at https://supabase.com and open your project.
2.	Navigate to the SQL Editor in the left sidebar.
3.	Create the six tables and their relationships according to the Django models defined in /backend/core/models.py. If a database initialization script is available, execute it in the SQL Editor.
4.	(Optional) Insert test data for development and testing.
5.	Copy the connection pooler host from Project Settings > Database and update DB_HOST in your .env file.

Note: The database connection requires the pooler host (port 6543) rather than the standard PostgreSQL port (5432).

3.4 Troubleshooting

Component	Details
Cannot connect to database	Check DB_HOST uses the pooler address (port 6543, not 5432). Verify DB_PASSWORD is correct. Confirm Supabase project is active.
npm / npx not found	Ensure Node.js 18+ is installed and added to system PATH. Restart the terminal after installation on Windows.
CORS errors in browser	Confirm Django server is running on port 8000 and CORS_ALLOW_ALL_ORIGINS = True is set in config/settings.py.
Port already in use	Stop other services using port 8000 or 5173. Alternatively change the port in settings.py or vite.config.js.
Python packages missing	Run pip install -r requirements.txt with the virtual environment activated.
1970 date on records	Run ALTER TABLE notifications ALTER COLUMN created_at SET DEFAULT current_timestamp; in the Supabase SQL Editor.

 
4. User Manual
4.1 Getting Started
Open a browser and go to http://localhost:5173. The login page is displayed by default. New users must register an account before they can log in.

The system has three roles: Customer, Operator, and Master. Each role sees different navigation links and features. The navigation bar adapts automatically after login based on the assigned role.

In-App Support


Registration Steps
1.	Click Register in the navigation bar.
2.	Enter your first name, last name, email address, and password (minimum 4 characters).
3.	Select your role from the dropdown: Customer, Operator, or Master.
4.	Optionally enter a phone number.
5.	Click Register. A success message confirms account creation.
6.	Navigate to Login and sign in with your credentials. You will be redirected automatically to your role homepage.

4.2 Customer Guide
Customers submit repair requests, monitor their progress, and view a history of past repairs.

Creating a Repair Request
1.	Click New Request in the navigation bar.
2.	Select the service type from the dropdown (e.g., Plumbing, Electrical, Furniture Repair).
3.	Enter a description of the problem.
4.	Enter the full repair address.
5.	Select a preferred date and time. The date cannot be in the past.
6.	Click Submit Request. The request is created with status New.

Tracking Request Status
Click My Requests to view all submitted requests. Each card shows the service, status badge, address, assigned master (if any), and creation date. Status values:

Component	Details
New	Request submitted and awaiting operator review.
Assigned	An operator has assigned a master to the request.
In Progress	The assigned master has started the repair work.
Completed	The repair has been finished successfully.
Cancelled	The request was cancelled by the operator.

Repair History
Click History to view all completed and cancelled requests. Use the filter bar to narrow results by status, service type, or date range. Click Apply to filter and Clear to reset all filters.

4.3 Operator Guide
Operators have full visibility over the system. They can view all requests from all customers, assign masters, update statuses, view statistics, and generate reports.

Viewing and Managing Requests
•	Click All Requests to see every request in the system with full details.
•	Use the Status dropdown on any request card to change its status directly.
•	Select a master from the Assign Master dropdown and click Confirm to assign.
•	Assigning a master automatically changes the request status to Assigned and sends the master a notification.

Statistics Dashboard
Click Stats to view a live dashboard. It shows: total request count, active requests, completed and cancelled counts, total and available masters, requests grouped by service type, and requests grouped by status. All counts update in real time from the database.

Generating Reports
Click Reports to access the report generator. Set optional filters for date range, service type, and status, then click Generate. A summary panel shows totals for the filtered set and a detailed table lists individual records. Click Clear to reset all filters and return to the full dataset.

4.4 Master Guide
Masters view their assigned jobs, update job progress, attach notes, and manage their availability.

Managing Assigned Jobs
1.	Click My Jobs to see all jobs assigned to you.
2.	Each card shows the service, status badge, address, description, customer name, and scheduled time.
3.	For a job in Assigned status, click Start Job. The status changes to In Progress.
4.	Add an optional note in the text area (e.g., parts used, issues found).
5.	Once finished, click Mark Completed. Status changes to Completed and the customer receives a notification.

Note: Only the master assigned to a specific job can update its progress. Attempting to update another master's job will return a 403 error.

Setting Availability
1.	Click Availability in the navigation bar.
2.	Check or uncheck the I am available for new jobs checkbox.
3.	Add optional notes such as working hours or job type restrictions.
4.	Click Save. An Available or Unavailable badge confirms the current status.

 
5. Notifications
The system sends in-app notifications to users when key events occur. A bell icon in the top navigation bar displays the number of unread notifications as a badge.

5.1 Notification Triggers
•	Master receives a notification when assigned to a repair request by an operator.
•	Customer receives a notification when their request status changes to In Progress.
•	Customer receives a notification when their request is marked Completed.
•	Customer receives a notification when an operator manually changes their request status.

5.2 Managing Notifications
•	Click the bell icon in the navigation bar to open the notification dropdown.
•	Unread notifications appear with a light blue background highlight.
•	Click Mark read next to any notification to mark it individually.
•	Click Mark all read at the top of the dropdown to clear all unread at once.
•	Click anywhere outside the dropdown panel to close it.

Note: Notifications refresh automatically every 30 seconds in the background. No manual page reload is required to receive new notifications.
